# ClaimTrack REST API

Base URL: `http://localhost:8080/claimtrack`. Every endpoint below is relative to it.

All `/api/**` endpoints use **HTTP Basic** authentication. Request and response bodies are JSON unless noted otherwise. Dates in request bodies use `dd/MM/yyyy`. Response timestamps use `yyyy-MM-dd HH:mm:ss`.

The live contract is in Swagger UI at `/swagger-ui.html`, with the raw spec at `/v2/api-docs`. Both are generated by springfox on the legacy baseline and move to springdoc during the upgrade.

## Policies

### `GET /api/policies` · `GET /api/policies/{policyNumber}` · `GET /api/policies/customer/{customerId}`

```json
{"id":1,"policyNumber":"POL-AUTO-1001","policyType":"AUTO","customerId":1,"customerName":"Maria Gonzalez",
 "coverageLimit":25000.00,"deductible":500.00,"annualPremium":1150.00,
 "startDate":"28/10/2025","endDate":"28/10/2027","active":true}
```

The seeded policies are `POL-AUTO-1001`, `POL-AUTO-1002`, `POL-HOME-2001`, `POL-HOME-2002`, `POL-HLTH-3001`, `POL-TRVL-4001` and `POL-LIFE-5001`. `POL-HOME-2002` has lapsed, which is useful for testing validation.

### `POST /api/policies/quote`

| Field | Type | Rules |
|---|---|---|
| `policyType` | `AUTO` \| `HOME` \| `HEALTH` \| `TRAVEL` \| `LIFE` | required |
| `dateOfBirth` | `dd/MM/yyyy` | required |
| `coverageAmount` | number | required, at least 1000 |
| `priorClaims` | integer | at least 0 |

```bash
curl -u adjuster:adjuster123 -H 'Content-Type: application/json' \
  -d '{"policyType":"HOME","dateOfBirth":"12/04/1980","coverageAmount":300000,"priorClaims":1}' \
  http://localhost:8080/claimtrack/api/policies/quote
```

```json
{"policyType":"HOME","age":46,"coverageAmount":300000,"priorClaims":1,
 "annualPremium":1138.50,"monthlyPremium":94.88,"quotedAt":"2026-10-28 15:38:39"}
```

## Claims

### Claim resource

```json
{"id":15,"claimNumber":"CLM-20261028-00007","policyNumber":"POL-AUTO-1002","policyType":"AUTO",
 "customerName":"James Okafor","description":"Cracked headlight","claimAmount":980.40,
 "approvedAmount":null,"status":"SUBMITTED","fraudScore":30,"assignedAdjuster":null,
 "incidentDate":"26/10/2026","filedDate":"2026-10-28 15:38:39","lastUpdated":"2026-10-28 15:38:39",
 "notes":[{"author":"system","text":"Claim submitted. Fraud score 30 (MEDIUM)","createdAt":"2026-10-28 15:38:39"}]}
```

`status` is one of `SUBMITTED`, `UNDER_REVIEW`, `ESCALATED`, `APPROVED`, `REJECTED` or `PAID`.

### `GET /api/claims?status=ESCALATED`

Lists all claims. The optional `status` filter is matched against the enum name.

### `POST /api/claims` (first notice of loss)

| Field | Type | Rules |
|---|---|---|
| `policyNumber` | string | required |
| `description` | string | required, at most 2000 characters |
| `claimAmount` | number | required, at least 0.01 |
| `incidentDate` | `dd/MM/yyyy` | required |

Bean Validation on the request body runs first. Then the service applies business rules. Each rule that fails adds one entry to `details`:

* The policy must exist.
* The policy must have been in force on the incident date.
* The incident date can't be in the future.
* The claim must be reported within 365 days of the incident.
* The amount can't exceed the coverage limit.

The claim is then scored for fraud (see [ARCHITECTURE.md](ARCHITECTURE.md#fraud-scoring)). A score of **60 or more** sets status `ESCALATED` instead of `SUBMITTED`.

```bash
curl -u adjuster:adjuster123 -H 'Content-Type: application/json' \
  -d '{"policyNumber":"POL-TRVL-4001","description":"Luggage stolen","claimAmount":14000,"incidentDate":"27/10/2026"}' \
  http://localhost:8080/claimtrack/api/claims
```

The response is 201 with `"status":"ESCALATED"` and `"fraudScore":100`. A system note lists the triggered rules, for example `FREQUENT_CLAIMANT (+30), EARLY_CLAIM (+25), HIGH_COVERAGE_RATIO (+20), TRAVEL_HIGH_VALUE (+15), ROUND_AMOUNT (+10)`.

### `POST /api/claims/{id}/review`

Assigns the claim to the calling user and moves it from `SUBMITTED` or `ESCALATED` to `UNDER_REVIEW`. There is no request body.

### `POST /api/claims/{id}/decision` (MANAGER)

| Field | Type | Rules |
|---|---|---|
| `decision` | `APPROVE` \| `REJECT` | required |
| `approvedAmount` | number | optional; if left out, the payout is claimed − deductible, capped at the coverage limit |
| `comment` | string | optional; recorded as a note |

The claim must be `UNDER_REVIEW` or `ESCALATED` (otherwise 400). For an approval, the approved amount must be positive and can't exceed the claimed amount. A rejection sets `approvedAmount` to 0.

```bash
curl -u manager:manager123 -H 'Content-Type: application/json' \
  -d '{"decision":"APPROVE","comment":"Photos verified"}' \
  http://localhost:8080/claimtrack/api/claims/15/decision
```

### `POST /api/claims/{id}/pay` (MANAGER)

Moves an `APPROVED` claim to `PAID`. Paying the same claim again returns **409**:

```json
{"status":409,"error":"Conflict","message":"Illegal status transition PAID -> PAID for claim CLM-20261028-00007", ...}
```

### `GET /api/claims/{id}/fraud-assessment`

Re-runs the fraud rules without changing the claim.

```json
{"claimNumber":"CLM-20261028-00007","score":30,"riskLevel":"MEDIUM","triggeredRules":["FREQUENT_CLAIMANT (+30)"]}
```

### Documents

```bash
# Upload (multipart field "file", max 5 MB; not allowed on PAID or REJECTED claims)
curl -u adjuster:adjuster123 -F "file=@photo.jpg;type=image/jpeg" \
  http://localhost:8080/claimtrack/api/claims/16/documents

# List
curl -u adjuster:adjuster123 http://localhost:8080/claimtrack/api/claims/16/documents

# Download (checksum verified on the way out)
curl -u adjuster:adjuster123 -OJ http://localhost:8080/claimtrack/api/claims/documents/2/content
```

```json
{"id":2,"fileName":"photo.jpg","contentType":"image/jpeg","sizeInBytes":38,
 "checksum":"412AC08CDDF74626208C2259A8ADD3E8","uploadedAt":"2026-10-28 15:38:40","uploadedBy":"adjuster"}
```

`checksum` is an upper-case hex MD5. Keeping that exact format is part of the JAXB-removal exercise (catalog item A1).

### `POST /api/claims/import` (broker CSV feed)

A multipart field named `file` holds a CSV with the header `policyNumber,incidentDate,claimAmount,description`. Each row is validated and submitted on its own, so one bad row doesn't stop the rest of the batch.

Run `scripts/render-import-csv.sh` to render [sample-data/claims-import.template.csv](../sample-data/claims-import.template.csv) with dates relative to today.

```json
{"totalRows":9,"imported":4,"failed":5,
 "importedClaimNumbers":["CLM-20261028-00009","..."],
 "errors":["Line 6: Invalid claim amount 'abc'","Line 7: Unknown policy number: POL-UNKNOWN-9999",
           "Line 10: Expected 4 columns but found 2"]}
```

## Audit (MANAGER, AUDITOR)

### `GET /api/audit/events`

Returns the 100 most recent lifecycle events, newest first. `type` is one of `SUBMITTED`, `REVIEW_STARTED`, `ESCALATED`, `APPROVED`, `REJECTED`, `PAID` or `DOCUMENT_ADDED`.

```json
[{"type":"ESCALATED","claimNumber":"CLM-20261028-00012","status":"ESCALATED",
  "customerEmail":"priya.raman@example.com","customerName":"Priya Raman","occurredAt":1793182121857}]
```

> `occurredAt` is serialized as epoch milliseconds because it is a `java.util.Date` and Jackson's default is in effect. Converting it to `Instant` during modernization (catalog item J1) changes this wire format unless you configure Jackson. Contract changes like this are exactly what `scripts/compare-smoke.sh` is there to catch.

## Errors

Application errors share one body format, built by `GlobalExceptionHandler`:

```json
{"timestamp":1793182120445,"status":400,"error":"Bad Request","message":"Request validation failed",
 "path":"/claimtrack/api/claims","details":["incidentDate: must be in dd/MM/yyyy format"]}
```

| Status | When | `message` |
|---|---|---|
| 400 | Bean Validation failure on the request body | `Request validation failed` (`details` lists `field: message`) |
| 400 | A business rule fails (`ClaimValidationException`) | `Claim validation failed` (`details` lists each rule) |
| 400 | Malformed JSON, or a bad enum or argument | the parser message |
| 401 | No or bad credentials | Spring Security's default body, without `details` |
| 403 | Role not allowed | Spring Security's default body: `Access is denied` |
| 404 | Unknown claim, policy, customer or document | for example `Claim not found: 99999` |
| 409 | Illegal status transition | `Illegal status transition X -> Y for claim …` |
| 500 | Anything else | `Unexpected error: …` |

The 401 and 403 bodies come from Spring Boot's error handling, not from `GlobalExceptionHandler`. Their shape changes between Boot versions, which is why the smoke comparison expects `unauthorized.txt` to differ after Phase 2.
